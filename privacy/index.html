データの扱いについて。

bk Healthは、自分の健康・写真・スキンケアの記録を管理するためのiPhoneアプリです。必要な連携を本人が選び、データの保存先と利用目的を確認できるようにします。

1. 扱うデータと利用目的

本人が入力・撮影・取り込みを行ったデータを、個人の記録、比較、振り返り、在庫管理、バックアップと復元に使用します。模擬データと本人の記録は保存先を分けて扱います。

データ使用する目的
顔写真と撮影記録朝夜の記録、撮影日時・条件の確認、写真の比較と振り返り。写真から本人を識別する認証には使用しません。
体調・肌・むくみ・生活のメモ本人の体感や日々の様子を写真・数値と一緒に確認するため。
Appleヘルスケアの記録本人が読み取りを許可した睡眠、体重、歩数、ワークアウト、心拍数、安静時心拍数、HRVを表示・集計するため。ヘルスケアへの書き込みは行いません。
化粧品と使用履歴商品、未開封の個数、手入力の残量、使用期間、日々に使った商品を管理するため。
Googleの接続情報本人が選んだアカウントを区別し、許可したDrive・Gmail機能を利用するため。アカウント識別子、表示名、許可されたアクセス範囲を扱います。

カメラ、写真ライブラリ、通知、ヘルスケアの権限は、対応機能で必要になったときにiOSの仕組みで確認します。権限のない記録や取得できなかった値を、測定済みのゼロとして扱いません。

2. Googleとの連携

本人によるログインと許可

Googleの認証画面を使い、本人がアクセスを許可します。Googleのパスワードをbk Healthの入力欄で収集することはありません。Google Sign-In SDKが接続用トークンを端末のKeychainで管理し、トークンを健康記録のファイルやこのWebサイトへ書き出すことはありません。

Google Drive：写真と撮影記録のバックアップ

https://www.googleapis.com/auth/drive.fileを使用し、アプリが作成・使用する特定のDriveファイルを扱います。Drive内のすべてのファイルを管理する権限は要求しません。

写真と写真付き日記を端末内で暗号化してから、本人のGoogle Driveへ送信します。写真付き日記には、撮影日時、朝夜の区分、撮影条件、メモ、体感評価、食事やケア、選択した使用商品名などが含まれます。自動バックアップは本人が有効にした場合に、アプリ使用中に実行します。

Gmail：化粧品の購入候補の取り込み

Gmail連携に対応する版で、本人が連携を開始した場合にhttps://www.googleapis.com/auth/gmail.readonlyを追加で求めます。この権限はGmailのメールと設定を読み取れる権限です。アプリが指定する購入関連の検索条件・期間・取得上限は、Google側の権限をそのメールだけに限定するものではありません。

対象メールの本文や必要なヘッダー情報を取得し、端末内で商品名、購入元、注文・明細の識別情報、数量、日時、注文・配送状況などを解析して候補を表示します。解析では外部AIへ本文を送信せず、メール内の画像やリンク先を自動で読み込むこともありません。メールの送信、返信、削除、ラベル変更は行いません。

メール本文全体、配送先住所、決済情報を在庫へ保存する設計ではありません。本人が確認して取り込んだ商品・数量などと、二重追加を防ぐための識別情報をアプリの記録に保存します。メールが注文・発送を示す場合でも、家に届いた在庫とは自動判定せず、受領の確認を求めます。HTMLメール内にある構造化情報（JSON-LDやMicrodata）から、注文番号・明細番号・数量を確認できる形式を候補にします。文字コードはUTF-8、およびメールに明示された対応する日本語文字コードを扱います。候補にできない場合は、本文から引用しない定型の理由を表示します。通常の文章だけのメールや商品コードだけの明細など、対応外のメールは手入力などで確認してください。

3. 保存とバックアップ

写真、健康数値、日記、在庫・使用履歴は、端末内のアプリの保存領域で暗号化して保持します。メール本文の解析は取得中の端末内で行い、本文全体を健康記録のアーカイブやバックアップへ保存しません。

  • Google Driveへの写真バックアップ：写真と写真付き日記を保存します。健康数値、写真のない日記、在庫台帳や使用期間全体は対象に含みません。写真付き日記で本人が選んだ商品名などは含まれるため、Gmailから登録した商品名が含まれる場合があります。
  • 全体のファイルバックアップ：本人の操作で、健康数値・日記・写真・在庫・使用期間・取り込みの重複判定情報を暗号化ファイルに書き出します。保存先は本人が選びます。
  • 復旧用パスワード：暗号化バックアップの復元に使用します。忘れたパスワードを運営側が確認・再発行して復元する仕組みはありません。本人が安全な場所に保管してください。

端末の記録は本人が削除するまで保持します。過去のバックアップは自動で一括削除されないため、端末で削除した写真や記録が、以前のバックアップに残ることがあります。Driveの保存容量や通信量は、本人が利用するGoogleアカウントと回線の条件に従います。

4. 外部への提供と利用制限

Google APIから取得したデータは、本人に見える上記の機能を提供するために使用します。広告配信、広告のターゲティング、データ販売、信用評価、汎用AIモデルの学習には使用しません。メール本文、写真、健康記録を解析のために外部AIへ送る機能は、この構成に含めません。

GoogleへのAPI通信と、本人が有効にした自分のDriveへの暗号化バックアップを除き、記録をアプリ運営者のサーバーへ集約する仕組みはありません。本人がファイルを書き出し、共有・保存先を選んだ場合は、その選択した先へデータが渡ります。外部の保存先やGoogleによる取り扱いは、それぞれのサービスの規約・プライバシーポリシーにも従います。

Mac：個人の持ちもの記録の書き出し

運営者本人のMacで動く書き出し処理が、同じGoogle Cloudプロジェクトのデスクトップ用クライアントでhttps://www.googleapis.com/auth/drive.fileを使い、本人のGoogle Driveのbk-exportフォルダに、持ちもの・ほしいものの一覧（品名・写真・使用場所など）を置きます。iPhoneアプリはこのフォルダを読み取り、アプリからの依頼をこのフォルダに書き込みます。健康記録や顔写真はこの処理で扱いません。Google の接続情報は Mac のキーチェーンに保存します。

bk HealthによるGoogle APIから受け取った情報の使用、および他のアプリへの移転は、Limited Use（限定的な使用）の要件を含むGoogle API Services User Data Policyに従います。Gmail由来データについては、Google Workspace API User Data and Developer Policyも適用します。

5. 停止・削除・許可の取り消し

  • 自動取得・送信を止める：アプリ内でヘルスケアの自動更新やDriveの自動バックアップをOFFにできます。設定を止めても、すでに保存された記録はそのまま残ります。
  • Google連携を止める：アプリ内で該当する連携を解除すると、その機能からのアクセスを停止します。これはGoogleアカウント上の許可の取り消しや、Driveのバックアップ削除とは別です。
  • Google側の許可を取り消す：Googleアカウントのサードパーティとの接続でbk Healthを確認し、接続を削除できます。同じGoogleアプリに許可したDrive・Gmailの両方へ影響する場合があります。再利用には本人の再接続が必要です。
  • HealthKitの許可を変更する：iPhoneのヘルスケアまたは設定からbk Healthの読み取り許可を変更できます。許可を外しても、取り込み済みのアプリ内記録が自動で消えるわけではありません。
  • 端末内の記録を削除する：日記や健康数値はアプリ内の削除操作で管理します。スキンケアの商品を一覧から保管扱いにしても、過去の使用記録に残した商品名は保持されます。端末の記録をすべて消したい場合は、必要なバックアップを先に確認し、アプリの削除を行ってください。KeychainにあるGoogleの接続情報がアプリの再インストール後も残る場合があるため、接続情報も取り消す場合はGoogle側の接続管理を併用してください。
  • バックアップを削除する：Google Driveや本人が書き出したファイルの保存先で、対象ファイルを別途削除してください。必要に応じてそのサービスのゴミ箱も確認します。バックアップを消すと、そこからの復元ができなくなるため、残す世代を確認してから操作してください。

6. このWebサイトについて

このサイトはアプリの紹介とデータの扱いを説明する静的なページです。健康記録やメールのアップロード欄、Googleアプリ連携のログイン機能、広告、独自のアクセス解析、追跡用スクリプトを設けていません。

ページを配信するホスティングサービスが、安全な配信・不正利用対策のために通常のアクセス情報を処理する場合があります。サイトに独自のCookieやトラッキングを追加していませんが、ホスティングサービスの認証・配信の仕組みはそのサービスに従います。

7. 変更と問い合わせ

扱うデータ、送信先、利用目的が変わる場合は、この説明とアプリ内の案内を更新します。新しい権限が必要な機能は、本人が確認できる手順で追加します。
